# Nium AML Transaction Monitor

A Streamlit dashboard that flags suspicious card activity. The pipeline:

```
CSV transactions → Python risk engine → FAISS policy retrieval (RAG) → Groq LLM narratives → Streamlit dashboard
```

- **Risk engine** (`risk_engine.py`) computes signals for each customer: transaction velocity, structuring, high-risk geography, high-risk MCC codes, late-night activity and decline rate. It combines them into a 0–100 score with LOW, MEDIUM and HIGH bands.
- **RAG** (`rag_engine.py`) embeds `policy_docs/*.txt` with `all-MiniLM-L6-v2` into a FAISS index. The index is cached with `st.cache_resource`, so it is built once per server process.
- **LLM** (`llm_engine.py`) sends the HIGH-risk customers to Groq. Groq returns a compliance narrative, monitoring rules and programme-review questions for each customer.

## Requirements

- **Python 3.12** (3.10–3.13 should also work). Python 3.14+ is not supported yet, because some dependencies (torch, zstandard) don't publish wheels for it.
- A free Groq API key from <https://console.groq.com>. You can run the app without one: risk scoring still works, but the AI narratives are skipped.

## Local setup

```bash
# 1. Create and activate a virtual environment
python3.12 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Add your Groq key (either option works)
cp .env.example .env                                      # then edit .env
# or
cp .streamlit/secrets.toml.example .streamlit/secrets.toml  # then edit it

# 4. Run
streamlit run app.py
```

Open <http://localhost:8501>. In the sidebar, either upload a CSV or turn on **Use sample data**, then click **Run Analysis**. The first run downloads the embedding model (~90 MB).

If you don't have Python 3.12, [uv](https://docs.astral.sh/uv/) can install it: `uv python install 3.12`.

## Configuration

The app reads settings from `st.secrets` first, then from `.env` and environment variables.

| Setting | Required | Default |
|---|---|---|
| `GROQ_API_KEY` | for AI narratives | — |
| `GROQ_MODEL` | no | `openai/gpt-oss-120b` |

> The original guide used `llama-3.3-70b-versatile`. Groq shut that model down for free and developer tiers on 2026-08-16 and recommends `openai/gpt-oss-120b` as the replacement. To use a different model, set `GROQ_MODEL`.

## Deploying to Streamlit Community Cloud

1. Push this folder to a GitHub repo. `.gitignore` keeps `.env`, `venv/` and `.streamlit/secrets.toml` out of the repo.
2. On <https://share.streamlit.io>, create a new app with `app.py` as the entry point.
3. Under **Advanced settings**, choose **Python 3.12** and paste your secrets:
   ```toml
   GROQ_API_KEY = "gsk_..."
   ```
4. Deploy. `requirements.txt` pulls CPU-only PyTorch, which keeps the install small enough for Community Cloud.

## Sample data

`data/sample_transactions.csv` contains 406 synthetic transactions for 50 customers, generated by `generate_sample_data.py` with a fixed seed. Running it again reproduces the same file.

| Customers | Pattern | Expected level |
|---|---|---|
| C001–C005 | Combined: structuring, high-risk countries, gambling/crypto/wire/ATM, late-night bursts, probing | HIGH |
| C006 / C007 | Velocity burst (C006 also late-night) | MEDIUM / LOW |
| C008 / C009 | Structuring just under $10k (C008 via wire MCC) | MEDIUM / LOW |

| C012 / C013 | High-risk MCC: gambling at night / crypto | MEDIUM / LOW |
| C014 / C015 | Late-night activity (C014 also ATM cash) | MEDIUM / LOW |
| C016 / C017 | Card probing: many small declined transactions | LOW (shown as a signal) |
| C018–C050 | Normal spending | LOW |

## CSV format

Required columns: `customer_id, transaction_datetime, merchant_country, MCC_code, amount`.

Optional columns: `authorisation_outcome, customer_tier, cross_border_flag`. If `cross_border_flag` is missing, any country other than Singapore counts as cross-border. The full schema:

```
record_id, customer_id, transaction_datetime, merchant_country, channel,
merchant_category, MCC_code, amount, currency, authorisation_outcome,
customer_tier, cross_border_flag, high_risk_merchant_flag, risk_flag
```

## Notes

- `langchain-community` is deprecated upstream but still works. It is only used for the FAISS vector store, because no official standalone LangChain FAISS package exists yet. Text splitting and embeddings use the current `langchain-text-splitters` and `langchain-huggingface` packages.
- Narratives are cached by their inputs (`st.cache_data`), so re-running the same data doesn't spend extra Groq tokens.
